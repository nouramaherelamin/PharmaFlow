Project Overview

Project Goal

Build an ELT-based pharmacy data engineering solution that loads raw pharmacy transactions into SQL Server, transforms and organizes the data inside the database, and presents business insights through an interactive Python and Streamlit dashboard.

Core Architecture

The pipeline follows Extract, Load, Transform (ELT). Raw records are loaded into SQL Server staging first; cleaning and business transformations then run inside SQL Server. Apache Airflow orchestrates the workflow, while Streamlit provides the analytics interface.

Project Scope

  • Ingest and stage raw pharmacy transaction data.
  • Profile data quality, clean values, derive business metrics, and validate results.
  • Model a pharmacy Data Warehouse using a Star Schema.
  • Orchestrate ELT tasks with Airflow and Docker.
  • Prepare SQL analytics and business KPIs.
  • Develop an interactive Streamlit dashboard using Python, Pandas, and Plotly.
  • Test, document, and prepare the project for presentation or deployment.

Out of Scope

The project focuses on analytics and data engineering, not on operating a live pharmacy point-of-sale system, prescribing medicine, or replacing professional inventory and clinical systems.

Phase 1: Data Ingestion & Staging Layer

Objective

Extract raw pharmacy transactions from a CSV file and load them into SQL Server while preserving the original data and preventing unintended duplicate loads.

Tools & Technologies

  • Apache Airflow (PythonOperator and XCom)
  • Docker and Astronomer Astro CLI
  • Python: csv, pathlib, and logging
  • Database drivers: pymssql and pyodbc
  • Microsoft SQL Server and environment variables stored in a .env file

Implementation Activities

  • Configure the Airflow environment using Docker and Astro CLI.
  • Create dags/pharmacy.py with three sequential tasks: extract_csv, connect_to_sql_server, and load_data_to_sql_server.
  • Validate the CSV structure and establish a connection to SQL Server.
  • Load the raw records into the staging table.
  • Implement duplicate-load protection and execution logging.

Input: Pharmacy_OLTP_SLStyle_18Months.csv containing 50,000 records and 27 columns.

Expected Output: stg.pharmacy_raw_staging containing the ingested raw transactions.

Phase 2: Data Profiling, Cleaning, Transformation & Validation

Objective

Assess data quality, standardize the dataset, perform business transformations inside SQL Server, and validate the results.

Tools & Technologies

  • Microsoft SQL Server and SQL Server Management Studio (SSMS)
  • SQL queries, views, and validation scripts

1. Data Profiling

  • Verify record counts, transaction uniqueness, missing values, numeric ranges, and date consistency.
  • Identify 31,236 records with missing Strength_mg values.
  • No duplicate transaction IDs or expired-at-sale records were detected in the tested dataset.

2. Data Cleaning

  • Create clean.vw_pharmacy_sales.
  • Convert numeric and date fields to appropriate data types.
  • Apply TRIM and NULLIF to standardize text values.
  • Preserve missing values as NULL and validate the cleaned view's record count.

3. Business Transformation

  • Create clean.vw_pharmacy_sales_enriched.
  • Calculate gross sales, discount amounts, net sales, and days until expiry.
  • Preserve original sales amounts for reconciliation.

4. Validation & Testing

  • Compare record counts across data layers.
  • Validate financial calculations and expiry indicators.
  • Check transaction uniqueness and data completeness.

Expected Outputs

  • clean.vw_pharmacy_sales
  • clean.vw_pharmacy_sales_enriched
  • Data quality and validation reports
Status: Profiling and initial cleaning completed; transformation and final validation pending.
